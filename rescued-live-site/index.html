Built for the seat you are in

Enterprise, builders, research, and operators share one platform. Switch seats. The page stays put.

Run GenAI across tenants

Artemis AI is a multi-tenant GenAI platform. Each tenant keeps its own agents in Artemis, its routes in Apollo, and its view in The Bow. Artemis Core serves the answers.

  • One engine

    Artemis defines agents once, then each tenant uses them.

  • Shared mesh

    Apollo routes models without a separate stack per tenant.

  • One gateway

    Chat, sign-in, and conversations run through api.cutline-industries.studio.

Define the agent once

Builders work in Artemis: a system prompt, a set of skills, and memory that stays with the agent. Apollo can change the model underneath without a new definition.

  • System prompts

    Behavior is written next to the agent, not in a side document.

  • Skills

    Attach what the agent is allowed to do.

  • Memory

    Context stays with that agent across runs.

Hold the agent still. Change the model.

Apollo is a multi-provider model mesh. Research can send the same Artemis agent across providers and read the run back in The Bow.

  • Same agent

    The prompt, skills, and memory do not move.

  • Other models

    The mesh is how a route changes, not a rewrite.

  • Runs in The Bow

    What happened is visible in the console.

Operate from The Bow

The Bow is the console for tenants, agents, and runs. Behind it, the gateway reports whether Artemis Core is configured and serving, so operators see model status, not a guess.

  • The console

    Tenants, agents, and runs in one operating surface.

  • Live status

    The gateway reports configured, serving, and quality on /api/status.

  • Three routes

    A vLLM host, the Azure core, then a fallback stub.

Four parts. One platform.

Model mesh

Apollo

Apollo is a multi-provider model mesh. Swap a model without a rewrite. The same Artemis agent can run across providers, and the run comes back in The Bow.

  • One agent, more than one provider

Inference route

Artemis Core

Every chat message goes through the api.cutline-industries.studio gateway to /api/artemis/chat. Memory and knowledge snippets ride along as context, and the answer streams back from the first route that responds.

  • Streams over SSE from a vLLM GPU host when one is set
  • Falls back to the Artemis core on Azure Container Apps
  • Memory, knowledge, Drive, and files under /api/artemis
